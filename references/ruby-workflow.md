# Ruby 执行与改稿约定

仅在当前任务通过 SketchUp Ruby API 创建或修改模型时使用。本文件约束执行与数据更新，设计阶段、构件组织和交付范围沿用主文件。

## 执行条件

核实桌面版、目标版本与可用执行入口；系统 Ruby 和 SketchUp 内嵌 Ruby 的能力不同。未取得实际 SketchUp 执行能力时，交付可加载的 `.rb` 与精确步骤，标明未运行，不能以系统解释器的语法检查替代应用内验收。

使用当前版本支持的 API，遇到版本相关行为查阅文末官方文档。不因生成脚本而自动安装 SketchUp、扩展或新增远程服务。

## 参数表达

参数使用设计师可理解的名称，如开间、进深、层高、墙厚、窗宽与窗台标高；区分完成面净尺寸和结构控制尺寸。对同一墙洞与门窗总成使用共同尺寸依据，避免各自计算造成错位。

玻璃按实际框内边界及配合关系计算，区分外框与横梃尺寸；门窗上下口核对对应完成面、窗台和板底，保留设计高差。检查或修复仅针对本轮相关部位，不根据几何距离自动封闭有意开口或依据不明的缝隙。

长度进入 API 前显式使用 `.mm`、`.m` 等转换；SketchUp 内部长度以英寸存储，不能把普通数值直接解释为毫米。校验正负范围、净空及直接相关的几何条件，无法成立时说明具体参数冲突。

普通一次性任务可采用集中参数区。设计师需要自行反复调整时，优先使用简短的 `UI.inputbox`，显示名称、单位及现值；取消操作应直接退出。只有字段联动、预览或操作频率确实需要时才采用 `UI::HtmlDialog`，不要将开发面板作为交付前置条件。

## 对象定位与修改归属

将程序封装在专属模块中；新建对象放入命名明确的任务容器。执行前检查活动模型和编辑上下文，明确本次写入哪个层级，避免把全案写进正在编辑的组件。

需要接续更新的生成对象用自有属性字典保存稳定逻辑标识及必要的生成参数。显示名称可以改变，不作为唯一身份依据；复制或分支后需重新建立对象映射，避免标识冲突。不要向用户已有对象批量附加无关元数据。

改稿先匹配实际对象，再检查当前几何、变换、材料和共享定义与已知基准是否相符。只更新可判定的受影响属性；已有手改无法可靠合并时保留原对象并输出独立变体。缺少可用基准应明确说明，不能假定所有差异都可覆盖。

重复运行须识别已有成果，按当前请求选择更新、创建变体或提示无变化。不要无声叠加整套模型。用户明确要求整案替换时也仅针对已辨认的生成范围。

组件定义和材料都是共享资源：写入前判断影响到哪些实例或表面。唯一化组件并不自动复制其引用的材料；当某一变体需要独立配色时，还要隔离对应材料对象或采用明确的实例继承策略。

## 几何操作与事务

在正确的群组或组件实体集合中创建几何，原始边面保留默认标签。共享组件修改、变换组合及局部坐标要按其实际作用域处理，不能依赖屏幕上的视觉位置推断坐标值。

一轮可撤销的模型改动使用一次 `start_operation` 到 `commit_operation`；异常时调用 `abort_operation` 并报告失败对象和原因，避免嵌套事务。生成参数面板时，让一次用户确认对应一次合理的模型操作。

模型保存和外部文件写入不属于几何事务回滚范围。使用新的版本目标，检查保存结果和实际文件；写入失败时保留内存模型，说明尚未形成可交付文件。

编辑洞口需实际修改宿主几何或使用已验证的裁切方式；移动一个独立窗组件不保证墙洞随动。对洞口位置、边界、贯通及相邻饰面做本轮检查，避免遗留原洞或封面。

## 可复核的成果

具备 SketchUp 执行环境时验证运行、模型结构及保存结果，必要时重开文件。报告具体已验证操作，例如窗宽变化后洞口匹配、单实例唯一化后其他窗不变；没有执行的步骤标为待验证。

只有系统 Ruby 时，可做语法检查，但将它与 SketchUp API 可用性、几何正确性和原生文件保存分别报告。交付脚本时给出桌面版 Ruby 控制台的实际 `load` 路径，并说明一次运行的作用范围、重跑行为和撤销方式。
